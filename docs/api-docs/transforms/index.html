Read and write tabular data as streams of rows: CSV, TSV, JSON lines, and a record format meant for passing rows between programs.

Each function returns a transformer for .transform(). A parser takes bytes (from read() in @j50n/proc, a process's stdout, or any async iterable of Uint8Array) and yields rows; a writer takes rows and yields bytes, ready for .writeTo() or the stdin of the next process.

Formats

  • CSV: RFC 4180, with quoted fields and a configurable separator. fromCsvToRows, fromCsvToLazyRows, toCsv. csvToTsv and tsvToCsv convert bytes to bytes without making rows.
  • TSV: a tab between fields, a line feed after each row, no quoting. fromTsvToRows, fromTsvToLazyRows, toTsv.
  • JSON lines: one JSON value per line. Values, not rows. fromJsonToRows, toJson.
  • Record: FIELD_SEPARATOR (\x1F) between fields and RECORD_SEPARATOR (\x1E) after each record, no quoting. A field can hold anything else, tabs and newlines included, and a program in any language can split it with two calls. fromRecordToRows, fromRecordToLazyRows, toRecord.

None of the formats has a header row. A header is the first row, like any other; .drop(1) skips it.

Row or LazyRow

A Row is a string[]: every field is decoded when the row is parsed. A LazyRow from fromCsvToLazyRows or fromTsvToLazyRows keeps the row's bytes and decodes a field only when you call getField; fieldEquals compares a field without decoding it. Pick LazyRow when you filter on or read a few fields of each row; pick Row otherwise, since it is a plain array. Every writer takes either.

Batches

Parsers yield batches (arrays of rows), not single rows, so add .flatten() to work row by row. The row writers take a single row or a batch per item, and toJson takes one value per item, so flatten before it. Each item becomes one chunk of bytes.

Errors

A reader or writer throws rather than drop or change a row or field. A writer refuses a field its format can't hold: toTsv and csvToTsv refuse a tab, CR, or LF in a field, and toRecord refuses \x1E or \x1F; toCsv quotes instead. Every row writer refuses a row that would read back as no row or a different one (a row with no fields, and in TSV a row of one empty field) and a lone surrogate, which UTF-8 can't hold. The CSV and TSV parsers take lines ending in LF or CRLF and refuse any other CR outside a quoted field, a file with CR-only line ends included, and the CSV parser refuses a quote still open at the end of the input. The Error names the row (and field), counted from 1, as in Invalid character (tab) in TSV data at row 2, field 1. Invalid UTF-8 in the input throws a TypeError when it is decoded. Otherwise the CSV parser is lenient; see fromCsvToRows.

Examples

Keep the active rows of a CSV file, as TSV

import { read } from "@j50n/proc";
import { fromCsvToRows, toTsv } from "@j50n/proc/transforms";

await read("people.csv")
  .transform(fromCsvToRows())
  .flatten()
  .filter((row) => row[2] === "active")
  .transform(toTsv())
  .writeTo("active.tsv");

Interfaces

I
CsvParseOptions

Options for fromCsvToRows, fromCsvToLazyRows, and csvToTsv.

  • separator: string

    The field separator: one ASCII character other than ", CR, or LF. Default ",". Anything else throws a RangeError from the call that takes the options.

I
CsvStringifyOptions

Options for toCsv and tsvToCsv.

  • crlf: boolean

    End each row with CRLF instead of LF. Default false.

  • separator: string

    The field separator: one ASCII character other than ", CR, or LF. Default ",". Anything else throws a RangeError from the call that takes the options.

I
JsonOptions

Options for fromJsonToRows.

  • sampleSize: number

    Pass only the first sampleSize values through schema. The rest are yielded as JSON.parse made them, unchecked and untransformed, and are typed T only by assertion, as with no schema at all; so use it only with a schema that checks values without changing them. Default: every value.

  • schema: ZodSchema<T>

    Checks each value: what schema.parse(value) returns is the value yielded, so Zod defaults and transforms apply and unknown keys are stripped, and whatever it throws stops the stream. Default: no check.

Variables

v
BATCH_SIZE_BYTES: number

About how much input, 128 KiB, makes one batch. The CSV and TSV parsers read input in chunks of this size and yield the rows each chunk completes; the record and JSON-lines parsers end a batch once it holds this much text, so a batch can run over by one row.

v
FIELD_SEPARATOR: "\u{1f}"

Separates the fields of a record in the record format: "\x1F" (ASCII US).

v
RECORD_SEPARATOR: "\u{1e}"

Ends each record in the record format: "\x1E" (ASCII RS).
