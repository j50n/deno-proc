default

Run child processes from Deno the way a shell pipes them, with errors that reach one catch, and work with any async iterable using the Array methods you already know.

Examples

Capture a command's output

import { run } from "@j50n/proc";

const branch = await run("git", "branch", "--show-current").lines.first;
const files = await run("ls", "-1").lines.collect();

Handle a failed command

import { ExitCodeError, run } from "@j50n/proc";

try {
  await run("deno", "test").lines.toStdout();
} catch (error) {
  if (error instanceof ExitCodeError) {
    console.error(`${error.command[0]} exited with ${error.code}`);
  } else {
    throw error;
  }
}

Feed data into a command

import { enumerate } from "@j50n/proc";

const sorted = await enumerate(["cherry", "apple", "banana"])
  .run("sort")
  .lines
  .collect();
// ["apple", "banana", "cherry"]

Read a compressed file a line at a time

import { read } from "@j50n/proc";

const errors = await read("app.log.gz")
  .transform(new DecompressionStream("gzip"))
  .lines
  .filter((line) => line.includes("ERROR"))
  .count();

Do work concurrently

import { enumerate } from "@j50n/proc";

const urls = ["https://example.com/a", "https://example.com/b"];

const statuses = await enumerate(urls)
  .concurrentMap(async (url) => (await fetch(url)).status, {
    concurrency: 4,
  })
  .collect();

Let children shut down when the program ends

import { main, run } from "@j50n/proc";

await main(async () => {
  await run("./long-job.sh").lines.toStdout();
});

Convert CSV to TSV

import { read } from "@j50n/proc";
import { fromCsvToRows, toTsv } from "@j50n/proc/transforms";

await read("sales.csv")
  .transform(fromCsvToRows())
  .flatten()
  .filter((row) => Number(row[3]) > 1000)
  .transform(toTsv())
  .writeTo("large-sales.tsv");

ConcurrentOptions

Options for Enumerable.concurrentMap and Enumerable.concurrentUnorderedMap.

    How many calls of the mapping function may run at once. Default navigator.hardwareConcurrency. Fractions round up; below 1 throws an Error when reading starts.

I
ProcessOptions

Options for run and .run(), passed before the command: run({ cwd: "/tmp" }, "ls").

  • buffer: boolean

    Collect what proc writes to the child's stdin into chunks of at least 16 KiB before each write. Default false.

  • clearEnv: boolean

    Start the child with no environment but env, rather than this process's environment plus env. Use it to keep secrets in your environment from reaching the child. The program itself is still found on this process's PATH, but the child gets no PATH unless env has one, so a program it starts by name may not be found (shells fall back to a default). Default false.

  • cwd: string

    Working directory for the child. Default: this process's. A relative program path such as "./build.sh" is found from here, not from this process's directory.

  • env: Record<string, string>

    Environment variables to add to or override in the inherited environment. A PATH here changes where the program is looked up, so don't build env from untrusted input.

  • fnError: ErrorHandler<S>

    Change or suppress the error the process throws. See ErrorHandler.

  • fnStderr: StderrHandler<S>

    Read the child's stderr. See StderrHandler.

  • timeoutMs: number

    Stop the child after this many milliseconds: proc sends it SIGTERM, and reading its output throws TimeoutError once it has exited, however it exited. The timer starts when the child does and stops when it exits, so it bounds a child you stopped reading early, too. A child that ignores SIGTERM keeps running; proc never sends SIGKILL. On Windows, Deno's SIGTERM can't be caught: the child is ended at once. Programs the child started aren't signalled, and may hold its stdout open after it exits; once it has, a pause of a tenth of a second in the output ends it, so they can't hold up the error. A wrapper script should exec its program, so that the program gets the SIGTERM. Default: no limit.

Variables

v
BATCH_SIZE_BYTES: number

About how much input, 128 KiB, makes one batch. The CSV and TSV parsers read input in chunks of this size and yield the rows each chunk completes; the record and JSON-lines parsers end a batch once it holds this much text, so a batch can run over by one row.

v
FIELD_SEPARATOR: "\u{1f}"

Separates the fields of a record in the record format: "\x1F" (ASCII US).

v
RECORD_SEPARATOR: "\u{1e}"

Ends each record in the record format: "\x1E" (ASCII RS).
