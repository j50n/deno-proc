# A process's failure decision as one function

The stdout getter holds the library's error contract inline: `TimeoutError`
over `SignalError` over `ExitCodeError` over `UpstreamError`, then the
`fnError` rules. Every test of it spawns a child. From 008.

Decided: a pure function from the exit (status, timed out, upstream cause) to
the error, and one for handing it to `fnError`; the getter calls them.

Must not change: which error wins in each case, messages, `cause`, `fnError`
called only with an error or stderr data and never on an early stop, an async
`fnError` awaited.

Check: the suite; a table test of the precedence through the function.

Decided: `src/failure.ts`, internal (not re-exported by `mod.ts`), so the
functions stay out of the public API; it imports the error classes from
`process.ts`, and uses them only when called, so the import cycle is safe.
`fnError` is still read from the options when the run ends, as before.

Closed by 16e6eb7.

Verified: `tests/failure.test.ts`: seven `failureOf` cases (each type, the
precedence, messages naming only the program, `cause` present only when
given) and two for `settle` (no `fnError`; `fnError` only with an error or
data, awaited, a failed `fnStderr` as no data). Full suite 625 passed, all the
process, error and pipeline tests unchanged.
