# Optional escaping of CSV fields that look like formulas

A field starting with `=`, `+`, `-`, `@`, a tab or a CR opens as a live formula
in Excel and other spreadsheets (`=HYPERLINK(...)`), so CSV built from untrusted
data and opened by a person can run what an attacker wrote.

Wanted: an opt-in option on `toCsv` (and `tsvToCsv`, and the CLI) that prefixes
such fields with `'` so they stay text, as OWASP describes for CSV injection.
Opt-in, because it changes the data. Found in the pre-0.26.0 review (operator
frame).

Where: `toCsv` and `rowWriter` (`src/transforms/csv.ts`, `common.ts`),
`tsvToCsv` (`src/wasm/flatdata.ts` and the Swift converter), the `flatdata`
CLI's options.

Done: the option and its doc comment (what it changes, and that the data no
longer round-trips exactly), a line in the CSV page, tests for each leading
character and for a field that merely contains one.

Decided (j50n, 2026-10-06): "Standard CSV. Just follow the standard." Won't do:
`toCsv` writes RFC 4180 CSV, and guarding against formulas is for whatever opens
the file as a spreadsheet.
