# cache() fails when its storage does, and never expires entries

`cache()` throws after the cached function has already run when storing the
result fails: a value too large for Deno KV, or no `--unstable-kv` (it then
retries a TypeError three times, about 2.5 s). And expired entries are never
deleted, so the KV file grows with every new key. Both are documented; a cache
should still fail open.

Found in the pre-0.26.0 review (operator frame and iterables).

Where: `cache()` (`src/cache.ts`).

Done: a failed store returns the value anyway (reported how? to decide), the
retry only for errors worth retrying, entries stored with KV's `expireIn` set
from the timeout; doc comment and tests to match.

Decided (2026-10-06): a value KV can't store is returned and not stored,
silently: the call worked, only the caching didn't, and a library shouldn't
write to stderr. KV not enabled is different, a configuration error, so it
throws at once with a `TypeError` naming `--unstable-kv`; retries are only for
other errors (a database briefly held by another process). Entries get
`expireIn` from the storing call's timeout; reads still check age against their
own timeout. The whys are in `cache`'s doc comment and `openKv`.

Closed by 522c383.

Verified: `tests/cache.test.ts`, run in a child Deno with its own `DENO_DIR`
(sharing the module cache; checked that cleanup leaves the real cache's 1,265
files alone). "A value Deno KV can't hold is returned, uncached" and "Without
Deno KV, cache says how to enable it" fail on 0.26.1; "calls value once while
fresh" passes on both, as a baseline. Expiry itself isn't tested: KV deletes
expired entries on its own schedule.
