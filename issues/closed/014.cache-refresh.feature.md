# 014 cache: a refresh option (GitHub #34)

`cache`'s `timeout` both decides whether this call reads and how long its value
is kept, so there was no way to say "recompute now, and keep the result."
`timeout: 0` skips the read and the store. #34 asks for `refresh?: boolean`:
skip the read, call `value`, store as on a miss.

j50n, 2026-10-09: agreed with the issue; implement it.

Decided: a refresh whose value can't be stored (`null`, `undefined`, too large,
not cloneable, or `timeout: 0`) removes the old entry. Without that, a later
call would get the value the refresh replaced, which is the one thing a refresh
promises it won't. A refresh whose `value` throws leaves the entry as it was:
nothing was computed. Calls without `refresh` behave as before.

Closed by the commit that adds `refresh` to `cache`.

Verified: `tests/cache.test.ts`, "A refresh calls value even when fresh, and a
later call reads what it stored.", "A refresh that can't store its value removes
the old one." (fails with the delete removed), "A refresh whose value throws
leaves the old entry." The old tests pass unchanged; 635 in all.
