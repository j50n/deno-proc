# Find out what main() and terminateAll() do on Windows

On Windows `main` handles only SIGINT, and the children are signalled with
`ChildProcess.kill("SIGTERM")`. Deno on Windows probably ends the process
outright for that (TerminateProcess), so a child would get no chance to clean
up, and the book's promise of a clean shutdown wouldn't hold there. Not
verified; nobody here has a Windows machine.

Where: `SIGNALS` and `signalAll` (`src/shutdown.ts`); the book's Shutting down
cleanly page ("On Windows, only SIGINT is handled").

Done: the answer, from Deno's source or a Windows run, written down in `main`'s
doc comment and the book. If it is a hard kill, say so plainly; if there is a
gentler way to ask a Windows child to stop, a ticket for it.

Answer (2026-10-06, from Deno's source, main as of 2026-08-31): on Windows
`ChildProcess.kill` maps SIGINT, SIGTERM, SIGKILL, SIGQUIT and SIGABRT to
`TerminateProcess(handle, 1)` (`ext/process/lib.rs`, `deprecated::kill`, called
from `op_spawn_kill`). A child is put in a new process group only when detached
(`runtime/subprocess_windows/src/process.rs`), so a console Ctrl-C reaches
proc's children.

Decided (2026-10-06): after a Ctrl-C on Windows, `main` waits up to `timeoutMs`
without ending the children, since ending them would cut short the cleanup the
Ctrl-C started; on other endings they are ended (Deno would anyway, on exit).
Documented in `main`, `terminateAll`, `ProcessOptions.timeoutMs`, and the book's
"On Windows" section. No gentler way to ask a Windows child to stop is available
from Deno, so no follow-up ticket.
