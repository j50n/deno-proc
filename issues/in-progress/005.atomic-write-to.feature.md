# writeTo(path) that replaces the file only on success

`writeTo(path)` empties the file before it reads anything, so a failure leaves a
partial file, and `read(f)` feeding `writeTo(f)` finds `f` already empty. The
book shows the fix by hand (write a new file beside it and rename it over the
old one), and the flatdata CLI's `-o` now does exactly that.

Wanted: an option on `writeTo(path)` that does it for you. Found in the
pre-0.26.0 review (operator frame and iterables).

Where: `Enumerable.writeTo` (`src/enumerable.ts`); the model is `replace()` in
`scripts/flatdata/flatdata.ts` (follows a symlink, keeps the old file's mode,
writes devices in place, removes the new file on failure).

To decide: an option, or the default. As the default it changes what a failure
leaves behind, which is arguably what everyone wants, but it needs write
permission on the directory, not just the file.

Done: the option, its doc comment, the book's Files page using it instead of the
by-hand example, tests for success, failure (old file untouched, nothing left
beside it), and in-place rewriting.

Decided (j50n, 2026-10-06): an option, not the default. Existing callers keep
today's behavior; the safe one is asked for.
