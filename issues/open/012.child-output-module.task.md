# A child's stdout as one module

The reading of a child's stdout is spread over `pipeReader`, an on-exit
handler in the `Process` constructor, four fields and `output()`. Three fixes
in two releases landed in that coordination, the 0.28.1 crash (a stream
already locked by someone else) among them, and it can only be tested through
shells with grandchildren. From 008.

Decided: one internal module that takes the stream and owns the reading, the
drain at exit, the quiet cutoff after a timeout and the locked check, with a
small interface (read it once; the child exited, timed out or not). `Process`
keeps only the calls.

Must not change: no file left open by awaiting only `status`; output still
readable after `status`; `timeoutMs` not held by a grandchild; reading
`process.stdout` directly works; an early stop returns at once; `main` waits
for readers after a signal.

Check: the suite (third-review tests in particular); new tests of the module
on plain `ReadableStream`s for each behavior above; the fd probe.
