# A size limit for CSV and TSV rows

The readers hold a row whole until it ends, in WebAssembly memory that grows by
doubling and isn't given back until the stream ends. On untrusted input, a quote
opened near the start and never closed holds the rest of the file, about three
times its size, before the error. A service reading uploads can run out of
memory on a few at once.

Wanted: an option such as `maxRowBytes` on the CSV and TSV readers and
converters that fails as soon as a row passes it, with the row number, like the
other errors. Found in the pre-0.26.0 review (operator frame); the memory
figures are from the data review.

Where: the readers' options (`src/transforms/csv.ts`, `tsv.ts`), `readRows` and
the converters (`src/wasm/flatdata.ts`), and the check itself in the Swift
module (`swift/Sources/CSV/`), which knows the row's length as it grows.

To decide: a default limit or none (a default changes behavior for big honest
rows; the book says rows of hundreds of megabytes work).

Done: the option on every reader and converter that holds rows, documented in
the data pages' traps; tests at the limit and one byte over, across chunk
boundaries.
